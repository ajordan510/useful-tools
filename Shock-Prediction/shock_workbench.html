METHOD GUIDE · VERSION 1.0

From source evidence to component environment

This offline tool supports engineering screening and comparison. Device families describe the source; they do not supply calibrated amplitudes. The startup study and built-in half-sine are explicitly illustrative. Replace them with applicable evidence.

Start an assessment

  1. Create a source record with a measured or justified maximax acceleration SRS, or a uniformly sampled acceleration history. Record the reference location, direction, coordinate frame, configuration, valid bandwidth and evidence.
  2. Select the component interface and prediction method. For separation bolts, linear shaped charges, frangible joints and other families, use the appropriate measured reference and structural path. This release records source geometry as metadata; it does not resolve distributed loading or source initiation timing.
  3. Enter engineering allowance and additional test margin separately, with rationales. These are deterministic amplitude multipliers, not statistical tolerance bounds.
  4. Optionally compare against an achieved component test or nominal specification. Match Q, units, direction, frame, interface, configuration and mounting conditions. Run the study and inspect conditions alongside every coverage ratio.
  5. Save the project JSON. Export numerical CSV, a complete run manifest, standalone HTML report, or individual SVG plots. Data are held in memory until you download a project; there is no automatic cloud or browser storage.

Assumes rigid payload, prescribed base motion, no bypass paths and no contact. Travel beyond available clearance invalidates the linear prediction.

SRS calculation and import rules

SRS means absolute acceleration, maximax: the largest positive or negative response of each damped oscillator during and after the input record. Initial displacement and velocity are zero. The engine integrates a first-order-hold (piecewise linear input) state transition. It evaluates the forced response at at least 64 points per oscillator period and at least four substeps per input interval; these sampled peaks have a finite discretization error. Free-response residual extrema are evaluated analytically. A history is not reconstructed from an SRS.

The response displacement spectrum Sd is the maximum relative displacement; pseudo-velocity is ωSd and pseudo-acceleration is ω²Sd. Pseudo-acceleration is not the absolute acceleration SRS. History diagnostics report raw mean, peak, trapezoidal velocity change and ∫a²dt, and sample-bracketed 5–95% cumulative squared-acceleration duration. ∫a²dt is a signal metric, not structural energy.

Import exactly two columns, optionally with one header: frequency in Hz and acceleration for spectra; time in seconds and acceleration for histories; frequency in Hz and dimensionless ratio for transmission. Select g or m/s² explicitly. Standard gravity is 9.80665 m/s². Frequencies and spectrum levels must be positive; time samples must strictly increase and be uniform within 0.01% of the first interval (with a 10−10 s absolute floor). Comments beginning with # and comma, tab, space or semicolon separators are accepted.

Ordered spectra use log-log interpolation and never extrapolate. Imported spectrum and validity-band breakpoints are added to the logarithmic analysis grid to retain narrow empirical features. History-response peaks between oscillator frequencies still require a frequency-resolution convergence check. Imported SRS Q must match analysis Q; Q cannot be converted without a waveform or another justified model. History assessment is limited to the declared measurement band and sample rate/10. This conservative numerical limit is not evidence of sensor bandwidth or adequate anti-alias filtering. Mean subtraction is optional and explicit. Endpoints, bias and repeated peak samples raise inspection conditions; they do not prove acquisition quality.

The mount output includes 12 decay time constants of ringdown, followed by analytic residual SRS evaluation. Charts retain extrema while reducing long histories for display. Calculations use the full imported history. Limits: 30 sources, 40 assessments, 12 factors per assessment, 100,000 history samples, 600 base frequency intervals plus imported spectrum and validity-band breakpoints (2,000 ordinates total), and 30 million oscillator steps per SRS calculation.

Coverage, margins and missing data

Senvironment = Snominal10A/20; Srequired = Senvironment10M/20. A is the engineering allowance and M is the additional test margin. A source already marked MPE requires an explanation before adding allowance. No NASA/ECSS qualification margin is selected automatically.

Coverage = Scomparison/Srequired; coverage dB = 20 log10(coverage). A value below one identifies a numerical gap. Missing bands stay blank, and metadata incompatibilities or illustrative evidence make a favorable comparison conditional. Ratios shown for incompatible metadata are diagnostic only. Zero demand is unassessed. SRS coverage does not establish component survival, fatigue life, internal board stresses or qualification acceptance.

Envelopes group only matching component, interface, direction, frame and source configuration. They include all enabled assessments, including design alternatives; exclude alternatives when forming an event requirement. A maximum envelope is not the physical superposition of simultaneous inputs. Event counts, phase, correlation and source firing sequence require a separate analysis.

Verification and boundaries

Numerical verification is provided by executable engine, independent SciPy ODE and browser tests in the repository. See VALIDATION.md for executed results and tolerances. Verification of the oscillator mathematics does not validate a physical path model. No source hardware or attenuation calibration is bundled.

Complex FRF/MIMO propagation, FE/SEA solvers, frequency-dependent fitted distance exponents, statistical uncertainty propagation, automatic sensor correction and audited standards profiles remain future work. This release provides explicit evidence fields and deterministic screening, not those broader research capabilities.

Technical references

The repository's RESEARCH.md records reviewed primary sources and access limitations; FRAMEWORK.md and IMPLEMENTATION.md describe the broader roadmap. Relevant references include NASA-STD-7003, Pyroshock Test Criteria, ECSS-E-HB-32-25A, Mechanical shock design and verification handbook, and the NASA ShockSat data browser. Public ShockSat measurements have not yet been reproduced as validation cases here. These references inform the framework; this application is not a compliance implementation of a standard.
